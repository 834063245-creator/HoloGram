# ADR: Loop 纯度原则 — 主循环内非材料皆噪音

状态：**已采纳（2026-08-08）**

## 决策

**主循环内，一切非材料的东西都是噪音。** harness 只工作在两处：主循环之外，或补足模型/主 loop 的真实能力缺失。

新增 feature 时按以下三问决策：

1. 这个 feature 是否添加在主循环内？
2. 若是 —— 它是否补足模型或主 loop 的**真实能力缺失**？
3. 若非 —— 欠考虑，不做。

主循环之外的东西（合并验证、门禁、回滚、租约、多 Agent 调度）不受此测试约束——它们是 harness 的合法领地。

## 背景与推导

2026-08-08 的讨论收敛。出发点："图引擎 / Agent harness 工程究竟能不能提高工作能力"。

事实基线（无争议）：

- **Pi Agent 铁证**：四个原语 + 信任模型，在单 Agent、单进程、终端场景下追上 Claude Code。loop 内附加物（hooks、分析注入、花活工具）在该场景贡献为零。
- **模型消费规律**：模型对任何附加物遵循"能力缺失驱动"——感知不到自己缺能力，就 100% 不优先消费。分析类 MCP / 图查询恰好是模型永远觉得自己能做的（读代码推断依赖），因此必被冷落。这不是图特定的失败，是分析类附加物的结构性失败。
- **材料 ≠ 附加物**：文件内容、CLAUDE.md、错误信息、系统提示是模型工作的**原料**（Pi 也做 prompt 工程）。噪音指**附加物**：多余的 schema、注入的分析、强制的图上下文、花活的工具。

推论：

- 图死在 loop 内（MCP 查询、hooks 注入、分析喂给模型——全部是附加物）。
- 图的活路只在 loop 外（merge 落盘前验证依赖边、影响面计算——补机制需求，不补模型）。

## 对当前 agent 层的审计结果

| 分类 | 判定 |
|------|------|
| **真实能力缺失（留）**：多 Agent / 子 Agent 池、shell 执行、并行 tool call、merge 验证 / 回滚 / 隔离（loop 外） | 合法 harness |
| **材料（留）**：read / write / edit / search / glob | 合法 |
| **loop 内附加物（欠考虑）**：hooks 注入（图上下文 / 脆弱度 / LSP）、图 MCP 查询工具、`_forceGate` / 风险等级注入 | 删或移出 loop |

注：3D 星图 / 分析平台不住主循环，是产品形态问题，不在本 ADR 审计范围内，单独评估。

## 审计问题

- 🔴 hooks 注入（graph-context / state-read / plan 增强）：loop 内，不补能力缺失 → **移出或停用**
- 🔴 图 MCP 工具（trace_impact 等）：模型感知不到能力缺失 → **移出或停用**
- 🟡 `_forceGate` / 风险等级注入：loop 内附加 → **删**
- 🟢 子 Agent 池 / shell 队列 / merge 门禁：loop 外 → **保留**
- 🟢 read / write / edit / search / glob：材料 → **保留**

## 实施（待定，先记录决策）

| 阶段 | 内容 |
|------|------|
| 1 | 用此规则审计 agent 层完整工具清单，产出去留清单 |
| 2 | hooks 移出 loop 或停用，图 MCP 查询工具停用或移出 |
| 3 | 图引擎定位为 loop 外的验证基础设施（merge 门禁 / 影响面） |

## 不做

- ❌ loop 内再加任何"分析 / 注入 / 提示"类附加物
- ❌ 把图引擎重新做成模型可消费的分析平台
- ❌ 为"看起来有用"而做的可视化 / 注入 / 报告
