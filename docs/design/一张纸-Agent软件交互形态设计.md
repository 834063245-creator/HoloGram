# 一张纸 —— Agent 软件交互形态设计（The Paper）

> **状态**：探索性设计文档（2026-08-08 起）
> **目标**：定义一种脱离现有 Agent 软件交互范式的界面形态 —— 「整个窗口是一张纸」
> **可运行原型**：`prototype/paper-prototype.html`（深色版）、`prototype/paper-prototype-light.html`（白纸版）
> **关系**：本文档是未来「通用 Agent 桌面前端」（替换 HoloGram 前端）的设计地基

---

## 一、为什么是「一张纸」

### 1.1 现有 Agent 软件的两条错路

| 形态 | 代表 | 问题 |
|---|---|---|
| 聊天式 / CLI | ChatGPT、Claude Desktop | 只有时间维：信息被压成一条线，块与块无法建立空间关系。无聊，因为把多维信息坍缩成一维 |
| IDE 面板式 | Cursor、Windsurf | 空间被预分割：用户必须理解「面板」这个抽象概念才能用。心智负担拉满 |

### 1.2 「纸」的本质

- **纸有边界，但不是固定小框**：内容比视口大的大纸，平移/缩放看不同区域 —— 10 寸屏看局部，32 寸屏看全貌，空间支配权在任意屏上都成立
- **纸内排版自由**：非文档流，块可任意组织（写中间、画角落、圈起来、箭头连接）
- **纸是「物件」不是「控件」**：有坐标、有尺寸、有材质、有生命周期，可被放置、缩放、批注

### 1.3 核心隐喻：卷轴

聊天框是「卷轴的幽灵」——保留了卷轴的单向流动（append），却砍掉了卷轴的所有物性：

| 卷轴本有 | 聊天框现状 |
|---|---|
| 回卷（回到任意时刻） | 滚动（滑过，无停留感） |
| 摊开（整卷铺开） | 无（永远只看一个窗口） |
| 批注（边缘写字、划线、标记） | 无 |
| 截断（剪下一段留存） | 复制粘贴（脱离上下文的死纸） |
| 重排（重组合并段落） | 无 |
| 涂改（划掉重写） | 只能整条删 |

**产品定位一句话：把聊天框重新变回卷轴，找回它作为「可动手的物件」的全部物性。**

## 二、形态定义

### 2.1 一张纸 = 整个窗口

```
┌──────────────────────────────────────┐
│  整个窗口就是一张纸（唯一的容器）        │
│   ┌──────────────────────────────┐  │
│   │  Agent 写字段落（纸中央）       │  │
│   │  隐约边界，像卷轴写字的区域      │  │
│   │  对话流在此续写                 │  │
│   └──────────────────────────────┘  │
│   拖出的卡片 / 批注 → 落在纸上         │
│   输入框 → 纸的一部分（底部）          │
└──────────────────────────────────────┘
```

**没有第二层**：没有 dock、没有侧栏、没有独立面板层、没有弹层。纸是唯一容器，其他全是纸上的东西。

### 2.2 两个所有权层（关键区分）

| 层 | 对象 | 性质 |
|---|---|---|
| **Agent 产出层** | diff 块、代码块、plan 卡片、工具卡 | 响应性：随对话流涌现/消退，由系统管理 |
| **用户自定义层** | 便签、参考文件、钉住的卡片、批注 | 主动性：用户放置，锚定纸面，用户完全支配 |

两层的转化通道（需极简，不出现复杂图层面板）：
- 用户「钉住」一个 Agent 产出块 → 从 Agent 层转用户层
- 用户放置的便签 → 可被 Agent 引用为上下文

### 2.3 交互模型

- **平移/缩放替代滚动条**：滚轮缩放（围绕光标）、拖空白平移。纸的边界感（有界，不跌入虚空）是「纸」与「无限画布」的本质区别
- **块拖出**：流内块可拖出到纸上任意位置（钉住），原位置留占位符，可收回
- **数据无限续写，渲染窗口化**：数据层全量永驻，渲染只画视口内（虚拟化），交互用平移 —— 三者各司其职

## 三、技术架构

### 3.1 三层分离（对抗 DOM 文档流）

```
真相层（数据）  ← 块物件：id / 类型 / 内容 / 状态(flow|pinned) / 世界坐标(x,y,w)
渲染层（DOM）   ← 按视口把物件画出来，随时可销毁重建（DOM 只是渲染器，不负责想）
交互层（事件）  ← 平移/缩放/拖拽，只改坐标，不碰 DOM 结构
```

**为什么必须这样**：DOM 的文档流模型（位置 = 上方内容累计高度、改一处重排全部、无自由坐标）与「纸」天然相悖。正解不是逃离 DOM，而是**让 DOM 干活不干政** —— 数据层是唯一真相，DOM 只是输出通道（Monaco/CodeMirror 已验证此路线：布局自管、虚拟化、数据独立）。

### 3.2 块协议（Block Protocol）

Agent 输出**语义声明**，宿主渲染成任意形态 —— 逻辑/表现分离（游戏行业三十年范式）：

```
LLM 输出: {"type":"diff","files":["a.ts"],"stat":"+42/-18"}
                 ↓ 宿主渲染器（可任意替换）
用户看到: diff 卡片 / 乒乓球 / 力导向小图 / 纯文本 —— 渲染自由
```

- **语义层**（模型输出）= 块类型声明，被协议约束成稳定形态
- **表现层**（宿主渲染）= 任意映射，可插拔、可换主题
- **契约层**（信息保真）= 块背后永远挂着完整语义，任何抽象表现可一键展开回原始形态

### 3.3 与 Pretext 的关系

项目已有 `src/lib/pretext/`（Canvas measureText 排版引擎，用于聊天虚拟化高度测量）。它已经是「数据/测量/渲染分离」的半成品 —— 从一维流升级到二维空间时，Pretext 的测量能力可直接复用（块的高度/尺寸用 Canvas 算，不触发 DOM 重排）。

## 四、视觉语言：白纸版

（原型 `paper-prototype-light.html` 验证的方向）

| 元素 | 处理 |
|---|---|
| 纸面 | 暖白米色（非纯白）+ 受光/背光渐变 + SVG 纤维噪点（multiply），像真的纸 |
| 桌面环境 | 深胡桃木色托底，纸的投影三层（远散光 + 近影 + 边缘），悬浮感 |
| 写字段落 | 纸中纸：比纸面更白一档 + 笔记本横格线 + 黄铜上下轴头线（卷轴暗示） |
| 文字 | 暖墨色（非纯黑），像墨水不像碳粉 |
| 代码块 | 浅灰底 + 深墨字，像打印在纸上 |
| plan 卡片 | 黄铜描边 + 极淡黄铜底 |
| 输入条 | 纸色浮起墨槽（白纸浮在桌面上） |

**与观测台（深色）的关系**：观测台是 HoloGram 的视觉血缘（暗色玻璃、星图）；白纸是通用产品的方向。两者可并行验证，最终取向待定。

## 五、与 HoloGram 现有架构的关系

### 5.1 图谱内化（核心决策）

- 3D 星图是**给人看的展示层**，对用户无可读性；图谱的真正价值是**给 Agent 的认知层**（`hologram_*` 工具：explore_deps / trace_impact / coupling_report / arch_blindspots 等）
- **决策：砍展示层，保留认知层**。Agent 侧零感知（工具照用），前端瘦身（three.js 渲染栈退役）
- 用户不直接看图谱，通过 Agent 的语言理解图谱（"影响 23 个文件，其中 X 是脆弱模块"）

### 5.2 换壳而非重写

HoloGram 前端早已为换壳做好准备（P2′ 重构：无头 ChatCore + bus 契约）：

| 资产 | 去向 |
|---|---|
| `agent/` 运行时（59 文件，零 UI 依赖） | ✅ 原封不动 |
| `provider/` 模型接入 | ✅ 原封不动 |
| Rust 引擎 + `hologram_*` 图谱工具 | ✅ 原封不动（Agent 继续用） |
| `ui/chat-session` / `chat-stream` / `chat-store`（★逻辑勿动） | ✅ 保留给新壳供能 |
| 装配层（main.ts / workspace.ts 的 UI 依赖） | 🔄 重写（只改接线方式） |
| 视图层（src/app/ 整棵树） | 🔄 换成「一张纸」形态 |
| 3D 星图（graph.ts 全家桶） | ❌ 退役（代码留存，不 mount） |
