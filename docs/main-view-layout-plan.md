# 主视图布局重构方案（讨论稿 · 已按用户意见修订）

> 记录：2026-07-19 · 来源：与用户的布局讨论
> 状态：**待用户拍板**，未排期。本文档是布局方向的存档，不是施工清单。

## 已否决项（不要再提）

- **聊天右移为右侧常驻列 —— 用户明确否决**。用户原话立场：所有把「文本对话」放到屏幕侧面的设计都让用户斜眼阅读，是愚蠢改动。聊天保持**底部居中信标**（pill/input/panel/hud 四态机、WAAPI morph 全部保留）。
- **总览 = fold 星系云视图 —— 用户明确否决**。星图的产品身份是「代码即星辰」，fold 云图把节点抽象掉，总览必须是未折叠的纯星场（这也是现状如此的原因，非疏漏）。
- 同源的三条星图既定原则（历史决策，勿翻案）：节点标签全删走「视觉纯享，hover 看详情」（`2e367d9`）；总览边透明度刻意压低（m 0.10→0.05→0.02，「总览看结构、聚焦看类型」，hover/focus 提亮补偿）；不做边 LOD（用户拒绝过）。
- **LOD hub 标签 —— 用户明确否决**。历史尝试过，带来巨大性能问题，不再复活任何节点标签层。

## 星图布局已认可方向（暂缓施工）

用户认可但明确「不要急着动手」（用量原因，2026-07-19）：

1. **螺旋盘倾角统一 + CPU 路径盘化**：星系盘朝向从随机（`tiltA/tiltB` 质心 hash）改为公共平面 ±10° 自然变化，形成"银道面"；CPU 两层力导球路径同步盘化，消灭 GPU/CPU 两路径产出不一致。涉及 `graph-layout.ts`。
2. **社区半径 cbrt→sqrt(m)**：按 2D 投影面积等密度，修大星系糊/小星系散。涉及 `graph-layout.ts:586`（`Math.cbrt(m) * 14`）与 spiral 的 `commR` 公式。

施工注意：`tests/ui/layout-golden.test.ts` 坐标钉板需有意更新；两条合并一期做，钉板只更新一次。

## Hover 重设计（向原型学习，暂缓施工）

原型依据 `prototype/observatory-concept.html`；现状差距与方案：

| 维度 | 原型 | 现状 | 方案 |
|---|---|---|---|
| 节点标记 | 黄铜瞄准环+4 刻度线（:785） | 仅提亮（interaction-controller:135） | 单个 `RingGeometry`+刻度 mesh，billboard 朝相机，hover 吸附节点、半径匹配 glow 尺寸；场景内方案零 DOM 开销 |
| 选中标记 | 旋转虚线环（:794） | 无 | `LineDashedMaterial` 圆环，animate 慢转；给 detail-card 选中态空间锚点 |
| tooltip 内容 | 类型·扇入 X·扇出 Y（黄铜数字） | 类型·度 N·🌌社区+路径 | 渲染时 O(E) 预算 inDeg/outDeg 数组；meta 改扇入/扇出（黄铜数字），保留社区与路径行 |
| tooltip 定位 | 跟光标+视口钳制 | 贴节点投影、无钳制（右缘溢出屏幕） | 保留节点锚定，补视口钳制 |
| 光标 | crosshair | 默认箭头 | 一行 CSS |

性能说明：全部为每帧 O(1) 单对象（一环、一虚线环、一 tooltip），与 LOD 标签的 DOM 量级性能坑无关。

落点：`graph-interaction-controller.ts`（环显隐）、`graph-highlight.ts` 或小新模块（两个环）、`graph-tooltip.ts`（meta/钳制）、`graph-chrome.css`（cursor）。一期装完；门禁 build + vitest 330 + CDP 合成 mousemove 截图核对。
- 顶栏 omnibox 合并、面板按钮去重、Zen 模式、网格淡出、bloom/节点降饱和、深空背景、minimap、状态栏仪器化 —— 用户表示「绝大部分没必要做」，除非日后重提，否则不施工。

## 保留的方案（用户认可方向）

诊断（证据见代码）：

1. **浮层无家**：六面板全部 `position: fixed` 浮在星图上（`dock-panels.css`），可多开、两侧夹击星图；dataflow/settings 无 rail 入口（`panel-def.ts` `side: null`）。用户对面板位置无肌肉记忆。
2. **仪器进场动画分散**：六个面板各自处理隐藏态位移（P6 修过一轮同步问题），本质是「六个独立浮窗」的架构税。

方案（聊天不动版）：

```
┌──────────────────────────────────────────────────┐
│ CommandBar 46px（不动）                           │
├───┬───┬──────────────────────────────────────────┤
│左 │仪 │                                          │
│rail│器 │        星  图（不被面板遮挡）            │
│46 │dock│      聊天信标：底部居中浮层（不动）      │
│   │tab│                                          │
├───┴───┴──────────────────────────────────────────┤
│ StatusBar 28px（不动）                            │
└──────────────────────────────────────────────────┘
```

- **左 = 仪器**：六面板统一收编进一个左侧 dock，左 rail 即竖排 tab 条；一次显示一个（可后续加上下分屏）；每个仪器有固定地址。面板开/关 = dock 容器一种滑入滑出动画。
- **星图 push 而非 overlay**：dock 开合时星图画布 resize（宽度 = 视口 − dock），面板不再盖图。3D 轨道场景天然抗 resize；过渡结束后由 focus-controller 顺手重新取景。
- **聊天信标保持底部居中浮层**：它是瞬态元素（随用随开），不参与 push；四态机与 morph 保留。
- **右 rail 去留**：check/constraints 挪入左 dock 后右 rail 清空，可整体删除（或留作将来观测员入口——若删，index/App.tsx 同步清理）。
- dataflow/settings 获得 tab 家（`side: null` 消灭）。

顺带的简化：dock 面板 fixed 浮层定位、各自隐藏态位移、右 rail 相关 CSS 全删；`panel-def.ts` 的 `side` 字段改为 tab 序。面板组件零改动（已是 store 喂养的纯组件），ChatCore 不动。

代价（诚实记录）：

- 仪器+仪器不能同开（tab 互斥；现支持 timeline+check 同开）。缓解：左 dock 上下分屏或拖出浮窗（后做）。
- 窄窗口（<1400px）三列拥挤，需响应式降级为 overlay。

迁移（每期独立可交付）：

1. **L1 左 dock 收编**：新建左 dock 容器 + tab 条，六面板迁入，`panel-def.ts` 改 tab 序，删右 rail。面板组件零改动。
2. **L2 星图 push**：画布随 dock 开合 resize + 相机重新取景。
3. **L3 收尾**：删浮层定位/位移残留、Esc 链复核、窄屏降级。

下一步：用户认可后先做 L1；如需先行视觉验证，出一个 prototype HTML 替代 `observatory-concept.html` 成为布局事实来源。
