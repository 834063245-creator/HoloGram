## 续窗口（2026-08-15 下午）：Rust 多级 mod 树 + cross_file/metadata 落库

### Rust 多级 mod 树解析（P0-1/P0-2 补充）
- `super::` 任意层级、`use a::b::{c, d as e}` 花括号多符号、`use …::*` 通配、
  `pub(crate) use` 可见性、内联 `mod tests { … }` 作用域归属、`mod x;` 声明树
  （含 Rust 2018 裸路径：先当前模块再 crate 根，最后才落外部 crate）。
- 真实项目 engine/src（110 Rust 文件）：import-path **642/642 = 100%**
  （本地模块 393 + 外部 crate 249，0 unresolved；此前 94 条 `super::*`/
  `super::super::…`/花括号全部解决）。
- import-binding：**197 bindings / 584 条引用边确定性改写**（此前 55/228）。

### cross_file / metadata 落库修复（P1-4 一半）
- MemoryIndex CSR 元组扩展为 `(target, kind_u8, coupling, delay, cross_file, metadata_handle)`，
  `collect_outgoing`/`collect_incoming`/`flatten_buckets`/`rebuild_csr`/pending 全链路同步。
- SQLite `bulk_replace_all` 与 `batch_upsert_edges` 写 `cross_file`/`metadata`；
  `load_all_edges` 读回。冷启动、快照、`to_graph`/`get_*_edges` 均保留两字段。
- 实测 engine/src 入库 imports 边：cross_file=1 与 metadata 100% 落库；
  `resolved_by`/`unresolved_import`/`external` 溯源不再丢。
- 顺手修掉 LSP 无条件 warm 全部 9 个服务器的孤儿进程缺陷：pipeline 与
  engine_status 按项目真实扩展名 `warm_filtered`。
